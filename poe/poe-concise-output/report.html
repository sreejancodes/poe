## Operating modes

- `plan <task>` (or a task description without a mode): write `plan.md` only, then stop so the user can review it. Do not split it into phases and do not edit implementation files.
- `split [plan-path]`: split a reviewed `plan.md` into phases and work units, then stop for user approval. Do not edit implementation files.
- `execute [plan-path]`: execute a plan that has been split and approved. If the plan has no phase briefs yet, say so and ask the user to run `split` first.

## Context policy: about 100k tokens per agent

- 100k is a **soft target**, not a hard limit. Never claim to know exact token usage unless a tool reports it; otherwise judge by how much has been read and produced.
- Hand over at a natural boundary, not at a number. When a worker nears the target, it finishes the step it is in the middle of (an edit in flight, a test run, a debugging thread that is about to resolve), then brings its progress notes up to date and returns `partial`. Going moderately over the target to finish a coherent step is correct; stopping mid-edit to respect the number is not.
- The orchestrator then starts a **fresh non-fork worker** for the remainder, pointed at the progress notes. Do not keep resuming a bloated agent.

In:
- `skills/poe/SKILL.md`

Out:
- `poe_report.py`, tests, report.html format.
- Config option / toggle for verbosity.
- Changing code-comment or commit-message style.
- Next-command block for execute/resume/report (not requested).
- Rewriting existing plans in `poe/` or `plans/`.

- "Interacting with the user" = chat replies + files user reads. Worker→orchestrator messages included (they feed parent context, so terse helps too).

     3	A Claude Code plugin with one skill (`poe`) and one subagent (`phase-worker`). It plans a task, splits it into work units sized for about 100k tokens each, and runs each unit in a fresh-context subagent that keeps file-based progress notes.
     4	
     5	Requires Claude Code v2.1.296 or later.
     6	
     7	## Installation
     8	
     9	This repository is both the plugin and its own marketplace. Add the marketplace, then install the plugin:
    10	
    11	```sh
    12	claude plugin marketplace add sreejancodes/poe
    13	claude plugin install poe@poe-tools
    14	```
    15	
    16	The same commands work inside a session as `/plugin marketplace add sreejancodes/poe` and `/plugin install poe@poe-tools`. Then run `/reload-plugins` or start a new session.
    17	
    18	By default the plugin is installed at **user** scope, so it is available in every project. Add `--scope project` to enable it only for the current repository, recorded in `.claude/settings.json`.
    19	
    20	### Update and uninstall
    21	
    22	Third-party marketplaces do not update automatically. To get the latest version:
    23	
    24	```sh
    25	claude plugin marketplace update poe-tools
    26	claude plugin update poe@poe-tools
    27	```
    28	
    29	To remove it:
    30	
    31	```sh
    32	claude plugin uninstall poe@poe-tools
    33	claude plugin marketplace remove poe-tools
    34	```
    35	
    36	### Offering it to everyone on a project
    37	
    38	Commit this to the project's `.claude/settings.json`:
    39	
    40	```json
    41	{
    42	  "extraKnownMarketplaces": {
    43	    "poe-tools": { "source": { "source": "github", "repo": "sreejancodes/poe" } }
    44	  },
    45	  "enabledPlugins": { "poe@poe-tools": true }
    46	}
    47	```
    48	
    49	Once a collaborator trusts the folder, the marketplace is registered for them. They still need to run `claude plugin install poe@poe-tools --scope project` once.
    50	
    51	## Usage
    52	
    53	Plugin skills are namespaced, so the command is `/poe:poe`:
    54	
    55	```text
    56	/poe:poe plan Build an HPV ORF analysis pipeline with tests and reproducible outputs
    57	/poe:poe split poe/hpv-orf-analysis/plan.md
    58	/poe:poe execute poe/hpv-orf-analysis/plan.md
    59	/poe:poe resume poe/hpv-orf-analysis/plan.md
    60	/poe:poe report poe/hpv-orf-analysis/plan.md
    61	```
    62	
    63	- **Plan** writes `plan.md` from what you asked for, keeping the approach simple and the code human-readable, then stops. Review the file, edit it or ask for changes, and repeat until you are happy with it.
    64	- **Split** takes the reviewed `plan.md` and splits it into phases and work units, each sized for one subagent at roughly 100k tokens. It then stops for approval.
    65	- **Execute** hands each work unit to a fresh `poe:phase-worker` subagent, which writes progress notes as it works. The orchestrator verifies each unit before moving on.
    66	- **Resume** uses the status file and progress notes to continue safely.
    67	- **Report** copies the session's logs and (re)builds `report.html`, a step-by-step view of what the orchestrator and each worker did. Execute and resume also build it automatically at the end, after `summary.md` and the log copy; if the build fails, the reply says so and the task carries on.
    68	
    69	## Files
    70	
    71	Everything for one task is written under `poe/<task-slug>/` in the directory where Claude Code was started. `poe/` is created if it does not exist.
    72	
    73	```
    74	poe/<task-slug>/
    75	  plan.md              what will be built and why
    76	  phases/NN-name.md    one brief per phase, listing its work units
    77	  status.md            state of every phase and unit
    78	  progress/NN-unit.md  running notes written by each worker
    79	  summary.md           execution summary, written at the end of execute/resume
    80	  report.html          step-by-step report built from the files above and logs/
    81	  logs/<session-id>/   copies of the Claude Code transcripts (.jsonl) of each session, including worker subagents
    82	```
    83	
    84	The copied logs contain the full conversation, including file contents and command output, and so does `report.html`. Normally add `poe/*/logs/` and `poe/*/report.html` (or all of `poe/`) to `.gitignore`.
    85	
    86	To build the report by hand, without a Claude Code session (needs Python 3.9 or later, standard library only):
    87	
    88	```sh
    89	python3 <plugin>/skills/poe/scripts/poe_report.py poe/<task-slug>
    90	```
    91	
    92	`<plugin>` is this repository, or the installed plugin directory. The script writes `poe/<task-slug>/report.html` and prints its path. It is a single HTML file with no external resources, so it opens offline.
    93	
    94	Tasks created by older versions in `plans/` can be moved with `mv plans/<slug> poe/<slug>`.
    95	
    96	## Thinking text in the report
    97	
    98	The report can only show thinking that Claude Code recorded in its transcripts. By default it records none, so each thinking step reads "thinking text not recorded". The overview and each transcript's totals show "thinking recorded: N of M blocks", so you can see whether it was on for a run.
    99	
   100	To record it:
   101	
   102	- Interactive sessions: set `"showThinkingSummaries": true` in `~/.claude/settings.json` (all projects) or in the project's `.claude/settings.json`. This also shows the summaries in the terminal. Workers are expected to inherit the setting from the session that starts them.
   103	- Headless `claude -p` ignores that setting. Pass the flag instead: `claude -p --thinking-display summarized "..."`.
   104	
   105	The recorded text is a summary of the reasoning, not the raw reasoning. Sessions that ran without it cannot be filled in later.
   106	
   107	Steps labelled "narration" are short progress updates Claude Code writes alongside thinking; they are shown as they are and not counted as thinking.
   108	
   109	## Context settings
   110	
   111	The 100k figure is a soft target, not a hard cap. A worker nearing it finishes the step it is in the middle of, updates its progress notes, and returns. The orchestrator then starts a fresh worker from those notes.
   112	
   113	`phase-worker` sets `autoCompactWindow: 150000`. This is a backstop above the target, so that automatic compaction does not interrupt a step at exactly 100k. It does not cap cumulative usage. Older Claude Code versions ignore the setting without warning.
   114	
   115	The `CLAUDE_CODE_AUTO_COMPACT_WINDOW` environment variable takes precedence over a subagent's `autoCompactWindow`. Setting it to 100000 would make workers compact at 100k regardless, so leave it unset or set it above the target.
